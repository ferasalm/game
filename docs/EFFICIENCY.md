# Efficiency system: same quality, fewer tokens

Why the rules in CLAUDE.md exist. Not loaded at session start. Built 2026-10-19 from reem-bot
(`docs/PORTABLE-PLAYBOOK.md`, the orchestrator skill, `tools/doc-check.mjs`) and feras-career
(`docs/EFFICIENCY_PLAYBOOK.md`), read critically, plus methods of this repo's own. Drop a rule when its why stops
being true.

## The budget
The owner is on Claude Pro ($20/month): a 5-hour usage window plus a weekly cap, shared with his other projects.
Money is fixed; **throughput is the limit**. Every turn re-sends the whole chat (cheap when cached, but it still
counts), so the costs are: what is loaded at start, how long a chat runs, what gets read, and output.

## 2. This repo's own methods
1. **Pure logic + headless tests.** Rules are checked by a test summary line, not by playing or screenshots.
2. **Summaries, not logs.** The balance harness prints one table for 1,000 battles; tools/check.sh prints one line
   per step and keeps full logs in `.check/` to grep only on failure.
3. **Levels as text.** A 20-line ASCII map plus JSON builds the scene; nobody edits a big `.tscn` by hand.
4. **Content as JSON with validation.** Balance changes are one-line diffs; the owner can tune numbers himself.
5. **Generated code map.** One purpose line per file feeds docs/MAP.md; the check fails when it is stale.
6. **Spec first.** An Opus chat writes a short spec (`docs/design/<feature>.md`, <= 60 lines, with acceptance
   tests); a Sonnet chat builds from it. The spec is the whole brief, so the build chat reads little.
7. **Small pictures only when judging visuals**: 640x360 screenshots (~300 tokens); regressions by pixel diff.
8. **Placeholders first.** Art never blocks code; Claude never opens art files to write code.
9. **Pinned engine version + strict parser.** Godot 3 habits and typos fail at import, before a debug loop starts.
10. **Asset and licence manifest from day one.** No costly audit before a release.
11. **CI builds the game.** The owner downloads a Windows build to play; no tokens spent on "how do I run it".
12. **Usage ledger** (docs/USAGE.md): one row per session with the share of the 5-hour window it used. After three
    sessions, the estimates in docs/BRIEFING.md are recalibrated from real numbers.

## 4. How the owner can save tokens (prompt tips)
- Put the whole job in the first message, with what you already know; each missing detail costs a round trip.
- Answer numbered questions by number ("1 yes. 2 skip. 3 use your default").
- Say "use your defaults and log them" when you don't mind; Claude then stops only for real blockers.
- Name the output and its size ("just the screenshot verdict", "max 10 lines").
- Say what better means ("feels slower than Octopath's walk"), not "improve it".
- Disagree once with "log decision: ..." so it is never argued again.
- `/clear` or a new chat between tasks; `/usage` to see what is left of the window; `/rewind` to undo a wrong turn.
